# 视觉无人机路线图

更新日期：2026-10-26。本文用于安排开发顺序；代码中存在某个模块，不代表它已经通过实机验收。
规则以 `test_1/` 的 RMUC 2027 比赛规则手册 V1.0.0（20261015）为当前依据，相关条款与实现边界见
[主 README 的规则说明](../README.md#规则依据与当前边界)。冲击判据仍有待定参数，不能由视觉框或丢目标判定有效冲击。

## 先确定第一阶段的终点

建议第一阶段只完成：**无人机在可靠定位下到达目标附近，发现目标，对准装甲板，在目标前的指定位置稳定停住。**

接触、接触后的恢复、返航和降落作为后续阶段。先把感知、定位和接近这条链路验证清楚，再增加任务动作。

## 把三件事分开

- **自身定位：我在哪里？** MicoVIO／其他定位来源提供无人机的位置与姿态；还需要验证 PX4 是否正确接收、融合，以及坐标系和时间是否一致。
- **目标视觉：目标在哪里？** USB 相机与视觉程序发现绿色灯、红蓝灯条和装甲板，输出目标中心、偏角；有可信的标定和几何／深度条件时，才能进一步输出米制位置。
- **飞行控制：怎样飞过去？** 任务程序根据定位和目标观测产生位置／速度等参考值，PX4 执行飞行控制。视觉引导时，PX4 仍然负责姿态与飞行稳定。

PX4 的 Offboard 模式允许外部程序提供控制参考，所需状态估计取决于控制量；“切换为视觉主导”应理解为**参考目标从导航位置变成视觉目标**，不是停止使用飞控或自身状态估计。参见 [PX4 Offboard 文档](https://docs.px4.io/main/en/flight_modes/offboard)。

数据流可以按以下关系组织：

```text
自身定位 ───────────────────────→ PX4 状态估计
                                   ↓
USB 相机 → 目标检测 → 跟踪 → 目标观测 → 任务决策 → 控制参考 → PX4
                                   ↑
                         有效性、时间、坐标变换
```

## 绿色灯与装甲板各自负责什么

**绿色灯：候选搜索线索。** 可以帮助缩小搜索区域或把相机朝向目标附近。它能否在需要的距离上稳定识别、是否常亮、是否会被遮挡，都要实测。绿色区域的像素大小和亮度不能直接当作可靠距离。

**装甲板：精确对准对象。** 先检测同色红／蓝灯条，再配成装甲板四边形，跟踪目标中心。达到连续稳定检出、观测新鲜且几何质量合格等条件后，再允许精细接近。

**二者之间需要确认几何关系。** 用户提供的图纸把绿色灯标在飞镖检测模块上，它不等同于装甲板中心或接触点。不同机构状态下的相对位置也需要确认；不能把绿色灯中心直接作为最终停靠／接触目标。

切换条件应来自实测，包含连续确认、有效期限和不同的进入／退出条件，避免因一两帧闪烁反复切换。先保留“导航 → 搜索 → 装甲板确认 → 精细对准 → 停住”的骨架；绿色灯可以作为搜索的辅助条件，不应成为所有流程必须依赖的唯一线索。

## 当前工程能提供哪些基础

- `camera_light_test`：YLR4K 等 USB/UVC 相机预览、帧率、红蓝灯条与装甲候选、阈值调节、抓图。
- `armor_auto`：独立装甲检测与临时目标跟踪、相机标定入口、基于标定与已知尺寸的姿态／位置估计。跟踪编号不是装甲数字身份。
- `demo_aim_cpp`：合成／可选 RealSense 输入和观测流水线，实时图像使用传统灯条/装甲候选检测。
- `px4_localization_cpp`：可选 MAVLink 定位与链路诊断入口；实际定位融合仍需要硬件验收。
- `demo_mission_cpp`：定位、坐标变换和任务状态机的模拟验证；并非飞行动力学仿真或真机控制执行器。

独立的 [2027 地图工程](../../rmuc_gazebo_map/README_zh-CN.md) 已验证已知静态地图下的 PX4 X500 起飞、
EGO 绕障和到达悬停，当前没有模拟深度感知，也未消费本工程的视觉观测或任务意图。
本工程的入口、坐标和接口边界见 [RMUC 2027 集成说明](rmuc2027_integration.md)。
当前仍缺少经过实机验证的完整实时导航与 Offboard 执行链路。绿色灯检测也需要单独增加和验收。
已有测试通过只能证明相应软件检查通过，不能证明相机测量、定位融合或自主飞行已经可靠。

## 按验收推进，不按功能数量推进

### 第 1 步：地面视觉能稳定工作

固定相机和真实目标，验证真实画面、实际处理帧率、曝光、红蓝灯条配对和目标跟踪。增加绿色灯候选检测，但先不接飞控。

验收依据：保存原始画面与检测日志；在明确的距离、视角和光照下统计检出、漏检、误检、目标丢失与处理延迟。断流或目标消失时，旧结果必须失效。

### 第 2 步：视觉输出值得相信

选定镜头、分辨率和对焦状态后标定相机，核对实际目标尺寸。先验证目标中心偏角，再验证需要使用的距离或三维位置。

- `bearing_yaw/pitch` 表示目标中心相对相机的左右、上下偏角，解决“往哪里看／对准哪里”。
- `normal_yaw/pitch` 表示装甲板表面法向的方向，解决“板面朝向如何”。
- 只有目标中心偏角不能唯一决定目标距离。米制接近需要另行验证 PnP、深度或其他测距来源。

验收依据：用已知距离、已知偏转和重复测量检查误差；参数未标定、几何不满足条件或数据过期时，输出无效。相机／镜头／成像分辨率发生变化后重新确认标定。

### 第 3 步：独立验证自身定位

验证定位模块到 PX4 的连接、融合结果、坐标轴方向、姿态、时间同步和异常处理。这个步骤可以与地面视觉并行推进，但必须在自主飞行集成前完成。

验收依据：静止、前后左右移动、升降和转动时的反馈都符合预期；定位重启、跳变或失效可以被发现。定位失效后的动作取决于届时仍可用的状态估计和 PX4 配置，不能预设一定能够悬停。

### 第 4 步：先用合成数据和仿真接起来

统一时间与坐标系，把视觉观测、自身定位、任务决策和未来控制输出接成一条链。现有任务模拟用于接口与状态机验证；
飞行动力学和静态绕障复用 [2027 PX4/EGO 仿真](rmuc2027_integration.md#从-no_demo-启动仿真)，
不另建一套旧地图入口。先复现预设起飞与绕障，再增加视觉目标到规划目标的有时效适配、状态反馈与退出处理。
保留唯一 Offboard 控制出口，禁止把 `segment_clear=true` 的离线夹具直接用于 2027 真实几何。

验收依据：目标丢失、误检、相机延迟、定位异常、连接中断时，系统不会继续按失效数据接近。先用合成观测检验“搜索 → 确认 → 对准 → 停住”的切换。真实录像目前用于视觉／电控资源联测，完整任务切换仍需另行集成验收。

### 第 5 步：真机验证到目标前停住

先在独立测试环境验证受控悬停与有限位移，再逐步加入视觉对准和有限接近。测试环境保留人工接管与明确的退出条件；
正式比赛的空中机器人要求全自动运行，急停遥控和比赛判罚要求按现行规则单独验收。

验收依据：停止距离、对准误差、重复成功率和各类退出动作都有记录。允许接近的范围根据相机和定位实测决定，不预先承诺“固定到某一米数就能切换”。

### 第 6 步：再扩展接触、恢复、返航与降落

在前面各项稳定后，确认任务规则、接触点、机构运动关系、机体尺寸与机械设计，再增加接触控制、退出恢复和后续航程。
接入比赛阶段/权限、允许的目标类别、实测场地边界和禁区验证，以及通过机库的通信链路后，才能讨论赛事流程闭环。
绿色灯与装甲板的检测通过，不代表已具备接触能力；接触时间和面累积冲量门限应等待正式明确及实际测评。

## 相机与镜头怎么决策

“短焦广角”有利于搜索覆盖和近距离保留目标，但相同分辨率下，远处的小目标占用像素更少。先明确需要的搜索距离和近距离视野，再用候选相机实测决定镜头。

当前图纸没有明确标注绿色发光面的实际尺寸，不能据此确认最远识别距离。后续至少需要发光面尺寸、实际处理分辨率、镜头视场角／标定结果、曝光和现场样本。发现绿色亮点、稳定跟踪绿色灯、可靠测量装甲板，是三个不同的距离指标。

当前 `config/armor_auto.yaml` 面向 YLR4K 的 UVC 彩色流，默认请求 640×480、30 FPS、MJPG；设备路径和实际支持模式须在实机确认。灯条配置为 `config/light_bars.yaml`，引用的 `config/ylr4k_rgb_calibration.yaml` 尚未提供，需独立标定，不能复用旧相机参数。其 0.135 m 灯条中心距和 0.056 m 灯条长度只适用于经过确认的那块目标，不能直接套到图纸中的其他模块。

旧相机专用程序与历史实验记录见[相机归档](../archive/astra_pro_20261023/README.md)。通用深度平面算法与输出回归保留，归档的手动测量程序不再作为活跃入口。

## 现在只抓三件事

1. **把现有相机＋真实装甲板的地面演示固定下来。** 记录设备、镜头、分辨率、曝光、检测配置与原始录像，形成可重复基线。
2. **完成这套成像配置的标定与角度验证。** 先验收目标中心偏角；距离输出另外用实测核对。
3. **做距离／视角／光照测试，再确定绿色灯的价值和视觉切换范围。** 记录绿灯候选与装甲板检测各自何时开始稳定，绿色灯不稳定时保留装甲板直接搜索路线。

暂缓项：仅凭图纸选定镜头、接触动作和完整返航任务。先把上述三项做成可重复演示，再进入定位与控制的联合验收。

## 后续代码架构的方向

按“设备采集 → 检测／跟踪 → 目标观测 → 坐标与定位 → 任务决策 → 控制适配”分层。算法层不直接写串口或控制电机；测试入口保持独立，集成入口复用同一套模块。

目标观测统一携带：采集时间、坐标系、目标类型／临时编号、像素中心、偏角、可选米制位置，以及各字段的有效性和有效期限。任务层先检查这些条件，再决定是否接近。

当前工程已按这些职责拆分；后续集成应复用现有模块，并保持接口中的坐标、时间与有效性约束。
